## 0. 一句话需求

把头像包（AI 生成与真人混合）按**人脸身份**聚簇——**簇 = 同一个人**——簇按可配置的属性键顺序**硬分区**（发色/发长/发型/肤色），簇内按**人脸相似度**排序，最后重命名。

## 1. 需求条目（R1~R11）

| 编号 | 需求 | 决策来源 |
|------|------|---------|
| **R1** | 输入为头像包目录，AI 生成与真人照片**混合**，全部属性阈值**不分档**（单配置） | 问答② |
| **R2** | **簇 = 同一个人**：人脸身份嵌入决定簇边界；属性不参与"谁跟谁一簇"的判定，只决定簇的排列位置 | 问答① |
| **R3** | 属性键：发色、发长、发型、肤色。**键顺序由用户配置**（GUI 可拖拽调序、可关闭任意键），默认 `肤色 → 发长 → 发色`（发型默认不进分区链，见 §4.3） | 问答⑤ + 校准轮① |
| **R4** | 硬分区：同属性值的所有簇，编号必须连续（目录章节式，可人工浏览/搬运） | 问答③ |
| **R5** | 簇内按相似度排序：以簇内 medoid（到其他成员平均相似度最大者）为代表，成员按到代表的嵌入相似度降序 | 问答①延伸 |
| **R6** | 同一人跨属性（如 2 张黑发 1 张金发）：整簇按**众数属性**归区，簇不拆 | 问答①隐含默认 |
| **R7** | 原图与裁剪/缩放变体**不设专门同源机制**：人脸嵌入相似度 99%+ 且按相似度排序 → 必然相邻。护栏仅两项：身份聚类阈值对变体包容；人脸区 pHash 作簇内排序并列裁决 | 问答⑦ |
| **R8** | 重命名默认 `簇号-序号.jpg`（簇号全局连续，1..N）；**另提供"纯自然顺序号"模式**（1.jpg, 2.jpg, ...，按**本次排序结果的全局位次**，不按原文件名顺序）。落盘两模式：默认**复制到新文件夹**（原包不动，输出 `xxx_sorted/`），可切换原目录直接重命名（两阶段改名 + 失败回滚） | 问答④ + 补问①② |
| **R9** | 无人脸 / 人脸质量不达标 / 读取失败的图统一沉到输出尾部**成一组、组内不细分**（其可测属性不用于尾部内部排序），不删不搬 | 补问③ |
| **R10** | **明确不做**：族群/人种识别（判别的是"视觉印象"而非事实，且 AI 头像非真人）、衣服/背景/动作维度、多模态大模型（VLM） | 问答⑥ + 前期讨论 |
| **R11** | 排序质量可度量：报告相邻相似度总和（F 值）与"最差相邻对 top-10"，无需真值标注即可比较配置好坏 | 设计要求 |
| **R12** | 编号**不补零**（1.jpg / 12-3.jpg）；目录浏览依赖资源管理器自然排序，预览报告内部保证正确排序 | 补问④ |

## 2. 管线：四阶段

```
① 标注 ──→ ② 身份聚簇 ──→ ③ 硬分区+排序 ──→ ④ 输出
(每图一次)   (簇=人)        (键序可配置)      (重命名+报告)
```

**① 标注**（每张图只做一次，全部落特征缓存，改配置秒级重放）：

| 产出 | 来源 |
|------|------|
| 身份嵌入（512 维）、脸框、5 关键点、无人脸标记 | 人脸检测+识别 |
| 发区掩码、皮肤区掩码 | 区域解析（§4.1） |
| 发色桶、肤色桶、发长桶 | 掩码几何/统计判定（§4.2） |
| 发型分组 | SigLIP2 嵌入（§4.3） |
| 整图 pHash、人脸区 pHash | 纯算法 |

**② 身份聚簇**：人脸嵌入做同人聚类（代表点法，防相似度传递把不同人串成一簇）；对齐质量门槛（侧脸/小脸关键点塌缩检测）让坏脸标记"人脸级无效"，进 R9 尾部，而不是带着坏嵌入排错位置。簇属性标签 = 簇内成员**众数**。

**③ 硬分区+排序**：按 R3 的键顺序对簇做层级分区（键序即分区序）；每个叶子区段内的簇按代表嵌入做贪心最近邻链排序；簇内按 R5 排序。每级报告 F 值。

**④ 输出**：预演 → 重命名（默认**复制到新文件夹**，原包不动；可选原目录直接改名，两阶段 + 失败回滚）→ 预览报告（属性列 + F 值 + 最差相邻对 top-10）。

## 3. 模型栈（3 个模型文件）

| # | 模型 | 职责 | 体积 | 来源 |
|---|------|------|------|------|
| 1 | SCRFD det_10g @640 固定 shape + ArcFace w600k_r50 | 身份嵌入、脸框/关键点、无人脸判定 | ~190MB | InsightFace 官方 / Immich HF 镜像；精度不足升 antelopev2 (R100) |
| 2 | MediaPipe multiclass selfie segmentation（主档）；face-parsing BiSeNet-R18 @512（升级档） | 发区/皮肤区/身体区掩码 | ~5MB / ~53MB | 社区 ONNX（senty-au） / MIT（yakhyo 等） |
| 3 | SigLIP2 ViT-B/16（FP32） | 发型嵌入（聚类/零样本/示例三模式） | ~350MB | onnx-community，Apache-2.0 |

运行时 onnxruntime-directml（本机 RX 7900 XTX + Win10）；全模型固定 shape 重导出 + IOBinding + session 池；CNN 转 FP16 实测、SigLIP2 一律 FP32（DirectML 上 FP16 LayerNorm 有崩溃案例；int8 量化模型在 DML 不可用）。许可不设限（仅本机自用）。

**性能预算**（量级估算，M0 实测校准）：检测+识别 20~40ms + 解析 5~15ms + SigLIP2 15~30ms + pHash 1ms ≈ **40~80 ms/张**，1 万张约 7~13 分钟。

## 4. 技术方案详述

### 4.1 发区/皮肤区掩码如何取

**主档：MediaPipe multiclass selfie segmentation**。MobileNet 底座、256×256 输入，一次前向输出 6 类逐像素标签：`背景 / 头发 / 身体皮肤 / 面部皮肤 / 衣服 / 其他配饰`。掩码上采样回原图。优点：体积几 MB、桌面 GPU 近实时、**头发+两类皮肤一个模型全覆盖**（肤色要用面部皮肤、发长要用头发，正好）。局限：256 分辨率边缘粗——对颜色统计和长度量测够用，对发丝级 alpha 不够（本需求不做抠图，无影响）。

**升级档：face-parsing BiSeNet-R18 @512**（CelebAMask-HQ 19 类，含 hair / skin / cloth / hat / neck 等）。分辨率高、类目细（可排除帽子污染发区），速度仍远快于旧式人体解析。当主档掩码质量不满足（如发色桶置信度持续偏低）时启用。

**无模型回退**（解析完全不可用时降级，功能不中断）：肤色用关键点定位的脸颊/额头补丁采样；发区用脸框上方几何窗口（已知短板：帽子/背景污染，只保证可用不保证准确）。

**掩码质量门槛**（三级共用）：目标类像素数 < 阈值（初始 48，可调）或掩码占比异常 → 该属性标记**无效**，不参与分区（无效簇统一落到"属性未知"尾区，不阻断整体排序）。

### 4.2 发色 / 肤色 / 发长如何判定

三者共用原则：**掩码向内腐蚀一圈再采样**（避免边缘与背景互染）；统计用**中位数**不用均值（抗阴影高光）；输出 = 离散桶（用于硬分区）+ 连续值（用于相似度加权）双份。

**发色**：
1. 发区像素 RGB→Lab，去除低饱和边缘噪声；
2. 色度空间 k-means（k=2~3）取主色簇（占比最大且 ≥ 置信阈值）；
3. 分桶规则（Lab/HSV 调色板，全部可配置）：
   - 无彩色判定（饱和度低于阈值）→ 按 L* 分：**黑 / 灰 / 白**；
   - 有彩色 → 按色相 + 明度分：**红棕 / 棕 / 金黄 / 彩色系**（蓝/绿/紫/粉各一桶，AI 头像幻想发色多，必须单列）。
4. AI 头像发色饱和干净，预期极可靠；真人照片黑棕色占绝对多数，桶间距离大，同样可靠。

**肤色（0-19 级，校准轮① 起）**：
1. 取"面部皮肤"类像素（解析已排除眼/眉/唇），浮点 Lab 直读中位亮度 L* 与色度 C*（**不做灰世界白平衡**——对纯皮肤像素集做灰世界会把色度中和成灰，校准轮①踩坑）；
2. 单调评分 `eff = (100 − L*) + min(C*, 22) × 1.0`：亮度为主、色度（黑色素信号）有界加分；
3. `eff ∈ [44, 92]` 线性映射到 **0-19 级**（数字越大越深），描述词按区间映射：**白皮肤 ≤5 / 黄皮肤 6-10 / 黑皮肤 ≥11**（区间用户可调）；
4. 已知边界（校准轮①实测）：阴影下的浅肤色与亮光下的深肤色在面部色块上可能同值（如 L*46 vs 41 的两例被判同档）——人眼的判断用了场景级色彩恒常性，纯色块无法复现；残余混淆留待 M3 零样本交叉验证。

**发长**（几何量测，**不需要枚举清单**——它是有序量）：

用脸框（检测）+ 发区掩码（解析）量三个数：发区在头皮区的平均厚度、发区越过下巴线的纵向延伸 d（以脸框高 H 为单位）、发区面积比。

| 桶 | 判定规则（初始值，实施期校准） |
|----|------------------------------|
| 光头 | 头皮期望区几乎无发区像素，且额头皮肤上探到脸框顶 |
| 寸头 | 发区平均厚度 < 0.15×H，且无越下巴延伸 |
| 短发 | 有体积，无越下巴延伸 |
| 中长发 | 0 < d ≤ 0.5×H（下巴到肩线段） |
| 长发 | 0.5×H < d（至画幅底或 1.2×H） |
| 超长 | d > 1.2×H |
| 盘束/扎起 | 发区面积大但 bbox 紧凑（宽度近头宽、高度 < 0.6×H），零样本交叉验证 |
| ≥（截断） | 半身画幅下发梢被画幅底切断 → 标"至少长发"，不强行定档 |

真人/AI 混合单阈值：以上规则按真人光照与画幅多样性留冗余；侧脸时发区 bbox 会偏大，接受粗分误差（硬分区只要求桶内连续，不要求桶边界完美）。

### 4.3 发型：为什么是 SigLIP2 B/16，以及"分型太多"怎么解

**先澄清分工**：光头、寸头、短发、中长发、长发是**发长轴**——有序几何量，由 §4.2 的掩码量测分桶，**与发型分类无关，也不需要任何清单**。"分型太多无法枚举"的是**发型**（卷直/波浪/辫子/马尾/丸子头/编发/刘海样式……）。

**发型键的三种模式**（GUI 可切，默认 B）：

- **模式 A · 固定清单零样本**：内置一份 ~20 类的常见发型清单（工具自带，用户可增删改），每类写一段中英文提示词，SigLIP2 直接打标签。适合"我要的就是这几个类"的场景。
- **模式 B · 嵌入聚类（默认，免枚举）**：发区图过 SigLIP2 取嵌入向量，对全包做聚类自动分成 K 组（K 自动或用户指定），GUI 每组自动展示代表图——**用户从头到尾不需要给出任何类目清单**，看图合并/拆组即可。分组结果作为硬分区键（或软排序权重，可配）。
- **模式 C · 示例标注**：用户拖几张图当示例（"这样的算一组"），其余按最近示例分配。适合包里有特殊发型、清单和聚类都不贴切时。

**为什么选 SigLIP2 ViT-B/16**：

1. **嵌入空间是真正的资产**：同一份模型同时支撑 A/B/C 三种模式——固定清单只是嵌入空间里的若干锚点，聚类和示例检索都是原生能力。换任何"固定发型分类器"都只给得出写死的类目，无法应对"分型太多"。
2. **零样本质量**：同尺寸下优于 OpenAI CLIP（B/32 档 zero-shot ImageNet 约 68~70%，SigLIP2 B/16 约 78~79%），sigmoid 损失对检索/最近邻类任务更友好。
3. **体积/速度**：~86M 参数、224 输入，DirectML FP32 下单张几十毫秒；要更准有 L/16、so400m 升级位（Apache-2.0，同族换文件即可）。
4. **许可与部署**：Apache-2.0，onnx-community 现成 ONNX，FP32 在 DML 稳定（ViT 不转 FP16）。

**输入构造**：不做矩形裁剪——用发区掩码生成"发区图"（非发区像素置灰）再过模型，避免背景/人脸信息污染发型嵌入。

| 发型聚类 K | 自动（轮廓系数选 K，上限 12） |
| 身份聚类阈值 | 0.55 余弦（起始值，含变体包容余量） |
| 无人脸图 | 输出序列尾部成组，组内不细分（R9） |

| MVP 交互 | M0~M2 命令行参数 + JSON/CSV 报告跑批；M3 提供 GUI（键序拖拽 / 预览 / 重命名） |
| 目标规模 | 按 1 万~3 万张设计，不设硬上限 |
| 缓存位置 | `~/.facecluster/cache/`（不进项目仓库） |
| 尾部区顺序 | 序列最末两段相连：有脸但属性无效 → 无人脸 |
